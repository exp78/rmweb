# Код-ревью rmweb — 2026-07-18

Ревью рабочей копии (ветка `phase6-batch1`, с некоммиченными изменениями).
Объём: ~3700 строк — `engine/wpeqt/main.cpp` (1736 строк), 8 header-модулей,
5 C-утилит, 20+ шелл-скриптов, тесты, CMake, Dockerfile.
Пять параллельных проходов по областям (ядро / заголовки / C-утилиты /
скрипты / тесты), часть находок верифицирована эмпирически (прогон тестов,
парсинг ELF динамических секций, проверка `mktemp`).

## Общий вывод

Проект **НЕ release-ready**, а документация (README, CLAUDE.md) приписывает ему
несуществующие фичи. Архитектура ядра и дисциплина многопоточности крепкие,
тестовый контур честный. Проблемы концентрируются в трёх местах: расхождение
документов с кодом, безопасность shell/профиля, хрупкость диагностики в условиях
«сегфолт = ребут устройства».

## HIGH

### 1. Документация описывает фичи, которых нет в коде
`README.md:5`, `CLAUDE.md:121`
Заявлены: «password manager with XOR+base64 secure storage», advanced autofill,
on-device JS console, user/content scripts, full history search, tabs.
Grep по коду — ничего из этого не существует. `profile.h` хранит только
bookmarks/history/settings; `UserContentManager` используется лишь для
content-blocker. Это ложные релизные заметки — для публичного релиза самое
damaging из всего списка. (Уязвимого XOR-«шифрования» паролей нет ровно потому,
что нет самого хранилища.)

### 2. Shell-инъекция от root через `system()`
`engine/wpeqt/main.cpp:257`
`system("mkdir -p '" + m_profileDir + "'")` с путём из env `RMWEB_PROFILE`,
без валидации и без проверки результата. Апостроф в пути = выполнение
произвольной команды от root. Молчаливый фейл mkdir → вся запись профиля
молча падает дальше. Заменить на `g_mkdir_with_parents()` (glib уже линкуется)
+ лог ошибки.

### 3. Root-инъекция через URL в dev-раннере
`scripts/run-wpeqt-on-device.sh:15`
`ssh ... "MODE='$MODE' URL='$URL' ... bash -s"` интерполирует URL и ~20
переменных `RMWEB_*` в удалённую команду. URL вида `http://x';reboot;#'`
выполняет команду от root на устройстве. В `run-on-device.sh:13` та же задача
решена правильно через `printf '%q'` — перенести паттерн. Продакшен-лаунчер
`device/rmweb:50` безопасен (позиционная передача `"$@"`).

### 4. Восстановление WebProcess может молча не работать
`engine/wpeqt/main.cpp:772`
`QTimer::singleShot(backoffMs, ...)` вызывается на worker-потоке без Qt event
loop — сработает только если Qt собран с `QEventDispatcherGlib` (зависит от
конфигурации Yocto-сборки). Иначе после краша WebProcess — белый экран навсегда.
Весь остальной файл использует `g_timeout_source_new` (напр. `:598`) — здесь
надо так же. **Требует проверки на устройстве.**

### 5. Потеря данных профиля при ENOSPC
`engine/wpeqt/profile.h:42`
`atomicWrite` не проверяет состояние потока после записи и не делает fsync.
На устройстве с переполненной ФС усечённый `.tmp` переименуется поверх целого →
закладки/история/настройки необратимо обрезаются. Без fsync файла и директории
«atomic»-rename не переживает выдёргивание питания. Вызывается при каждом
LOAD_FINISHED (`main.cpp:705`), каждом `toggleBookmark` (`:404`) и каждом зуме
(`:455`).

## MEDIUM

### Безопасность / сетевая модель
- **`rmweb:` scheme — confused deputy** — `main.cpp:321`, `startpage.h:61`.
  Любая внешняя страница может сделать `location.href='rmweb:clear-history'`
  и стереть историю. Разрешать только с внутренней home.html (проверка
  `webkit_web_view_get_uri()` == file://home.html) или одноразовый токен.
- **Сигналы `tlsChanged`/`titleChanged`/`processCrashed` никуда не подключены** —
  `main.cpp:241-246`. TLS-индикатора нет, комментарий про «broken-lock
  indicator» (`:246,:761`) врёт, код эмиссии мёртвый. Подключить и рисовать
  или удалить.
- **Тарболлы зависимостей без SHA256** — `scripts/build-wpe.sh:87-91`,
  `build-glib-networking.sh:35`. WPE WebKit, harfbuzz, libtasn1, libwpe,
  libxslt качаются голым `curl -fL`. SDK при этом запинен по хешу
  (`fetch-sdk.sh:7`) — несогласованно. Supply-chain дыра + невоспроизводимость.
- **URL в `href` стартовой страницы без whitelist схем** — `startpage.h:47,58`.
  `javascript:`/`data:` пройдут (сейчас безопасно лишь потому, что вызывающий
  код фильтрует по http(s) — инвариант не в генераторе). Defence-in-depth:
  whitelist в `buildStartPage` или при load.
- **`loadSettings` читает `ua` без `sanitizeField`** — `profile.h:91`.
  Control chars → User-Agent → HTTP-заголовки (файл редактируем по ssh).
- **Закладки не капнуты и не дедуплицируются** — `profile.h:28-38`. История
  капнута на 300, закладки — нет; дубль URL в файле рассинхронит UI↔store
  (`toggleBookmark` удалит первое вхождение, `isBookmarked` останется true).
- **`url.h:14` пропускает `file:///etc/...`** при ручном вводе (браузер от
  root). WebKit блокирует навигацию http→file, так что вектор локальный;
  whitelist http/https был бы безопаснее.

### «Сегфолт = ребут»: хрупкость диагностики
- **Crash handler не async-signal-safe** — `main.cpp:89-99`,
  `engine/wpe_cadence.c:23-32`. `backtrace()` (malloc при первом вызове),
  `fprintf`/`fflush` (локи stdio): краш внутри malloc = бэктрейс потерян именно
  там, где нужен. Обрабатываются только SIGSEGV/SIGABRT — SIGBUS (SHM-буферы)
  и SIGILL (llvmpipe JIT-ит код!) уйдут мимо лога. Чинится
  `backtrace_symbols_fd` + `write(2)` + прогрев unwinder в main (в
  `prof_preload.c` это уже сделано правильно) + `sigaltstack`.
- **`wpe_render.c:131-134` — нет валидации размера буфера.** `stride=size/h`,
  далее читается `w*h*4` без проверки `size >= w*h*4` — короткий `GBytes` =
  чтение за границей кучи.
- **`atomic16.c` — неполный ABI libatomic, шипится как единственная
  `libatomic.so.1` бандла.** Реализованы 5 из ~13 хелперов (нет
  `fetch_sub/and/or/xor/nand_16`, `test_and_set_16`, `clear_16`,
  `__atomic_is_lock_free`). Пребилт с UND-символом вне этих пяти = undefined
  symbol при загрузке. Нужен аудит: `objdump -T` всех .so бандла против
  экспортируемых хелперов.
- **Провал `EVIOCGRAB` только логируется** — `main.cpp:1357-1358`. Grab глушит
  crashing touch dispatch QPA; без него краш, от которого защищались, снова
  возможен. Падать явно или повторять попытку.

### Потоки / логика ядра
- **Гонка reader-apply с навигацией** — `main.cpp:552-568`. Eval может
  завершиться `'ok'` на новой странице → `m_readerMode=true` при показанном
  оригинале. Сохранять «поколение» загрузки (как `m_loadGen`) в callback.
- **Блокирующий файловый I/O на WebKit-потоке** — `main.cpp:705,455`.
  `saveHistory` на каждом LOAD_FINISHED, `saveSettings` на каждый тап A+/A- —
  синхронная запись на worker-потоке, который прокачивает WebKit. Debounce.
- **Логирование «всё подряд» в персистентный лог на флеше** — `main.cpp:62,842,
  1681`. `qInfo` на каждый кадр/тап/present + heartbeat 2 с. `Q_LOGGING_CATEGORY(lcEngine)` объявлен, но нигде не используется; комментарий про
  фильтрацию через `WEBKIT_DEBUG` неверен (Qt-категории — `QT_LOGGING_RULES`).

### Мёртвый код / расхождения с комментариями
- **`refreshpolicy.h` и `hintlabels.h` не используются нигде, кроме своих
  тестов** (2 из 8 тестов проверяют мёртвый код). Реальная refresh-политика
  живёт inline в `main.cpp:1488-1508` (full flash каждые 6 presents, rate-limit
  150 мс) и устроена иначе: нет `PresentKind::Idle/Motion`, нет `grayscaleMode`.
  Самый e-ink-критичный код не покрыт тестами. Подключить `RefreshPolicy` к
  `EpaperBridge` или удалить.
- **Мёртвый код «exit armed»** — `main.cpp:85,909-913,938,1206-1210,1419-1431`.
  `g_exitArmed`, `m_exitArmed`, `exitTapped()` недостижимы: тап по ⏻ сразу
  `std::_Exit(0)` (`:1647`). Двухтапового подтверждения нет.
- **Мёртвый include приватных Qt-заголовков** — `main.cpp:27` +
  `CMakeLists.txt:22`. `QWindowSystemInterface` нигде не используется, но тянет
  зависимость кросс-сборки от Qt6 private headers.
- **`RMWEB_UA=off` не очищает persisted UA** — `main.cpp:336-346`. Комментарий
  обещает очистку, `saveSettings` не вызывается.
- **Комментарий про DPR врёт** — `main.cpp:290`: фактический дефолт 2.0, не 1.0.
- **Шапка `wpe_cadence.c:81-88` описывает эксперимент с CSS-анимацией,
  которого в коде нет.**
- **Протухший комментарий `EpaperRefresh`** — `main.cpp:1456-1462` описывает
  ручной present как текущую архитектуру, а `main()` (`:1605-1611`) прямо
  говорит про self-deadlock и `RMWEB_MANUAL_PRESENT`-only.

### Сборка / деплой
- **rpath отсутствует, заявление в `package.sh:4` ложно** — проверено
  ELF-парсингом: ни `build/rmweb-wpeqt`, ни бандленные .so (кроме
  `libLLVM-16.so.1`) не имеют RPATH/RUNPATH. Работает только через
  `LD_LIBRARY_PATH` в `rmweb-env.sh:5`; прямой запуск `bin/rmweb-wpeqt` падает.
  Добавить `-Wl,-rpath,'$ORIGIN/../lib'` или `patchelf` в `bundle.sh`.
- **Битый шаблон `mktemp`** — `build-wpe.sh:78`, `build-vkb.sh:14`:
  `mktemp "..._dl.XXXXXX.tar"` (X'ы не в конце). На macOS создаёт литеральный
  файл `_dl.XXXXXX.tar` (коллизии при параллельных запусках), на GNU/Linux
  падает. Проверено эмпирически.
- **Неатомарный деплой** — `bundle.sh:69`: `tar | ssh 'mkdir -p ... && tar -xf -'`
  поверх живой установки. Обрыв ssh = половинчатое дерево (старые .so + новые
  ресурсы), перезапись библиотек работающего инстанса. Нужен staging + атомарный
  `mv`, учёт `.lock`.
- **Гонка stop/restore xochitl между dev-раннером и продакшен-лаунчером** —
  `run-wpeqt-on-device.sh:37,26`. `systemctl stop` без `is-active`-проверки
  (в `device/rmweb:36` она есть), лок `$R/.lock` игнорируется, безусловный
  `umount /usr/libexec` под чужим инстансом → два процесса гонят кадры на одну
  панель.
- **`CMakeLists.txt` без warning/hardening-флагов** — ни `-Wall -Wextra`, ни
  `-fstack-protector-strong`, `-D_FORTIFY_SOURCE=2`, `-Wl,-z,relro,-z,now`.
  Для root-процесса с «сегфолт = ребут» слабо. (Плюсы: `QT_NO_KEYWORDS`,
  `-rdynamic` с обоснованием.)
- **Mesa-сборка невоспроизводима из репо** — `build/src/build-mesa.sh` и
  `mesa-native.ini` живут только в gitignored `build/`, но от них зависят
  tracked-скрипты (`build-wpe.sh:171`, `build-wpeqt.sh:12`, `bundle.sh:15`).
  Чистый клон не соберёт полный бандл.

### UX-дефект

## Что сделано хорошо

- **Многопоточная дисциплина ядра**: все обращения к WebKit маршаллируются на
  worker GMainContext через `g_main_context_invoke_full` с destroy-notify;
  shared state трогается только на одном контексте; cancellable во всех
  async-колбэках; teardown с join'ами до разрушения stack-объекта.
- `onBuffer` (`main.cpp:778`): строгая проверка геометрии SHM до чтения
  пикселей, глубокая копия кадра до конца жизни буфера, дедупликация кадров
  FNV-отпечатком.
- Все JS-инъекции собираются только через `%d`-форматированные int'ы
  (tapLink/pageBy/zoomBy) — строковой интерполяции нет вообще.
- **`device/rmweb` — образцовый no-brick лаунчер**: атомарный mkdir-лок с
  DONE-гардом, идемпотентный cleanup на EXIT/TERM/INT, `is-active`-проверка —
  и всё это покрыто `tests/launcher_test.sh` со стабами systemctl/mount,
  включая TERM mid-run и lock-contention (лучшие тесты проекта).
- `run-tests.sh` честно агрегирует compile/runtime/shell-фейлы (проверено
  прогоном) — «зелёное всегда» не подтвердилось.
- `htmlEscape` полный (`& < > " '`) и применён во всех контекстах startpage;
  XSS-тест проверяет и наличие экранированного, и отсутствие сырого ввода.
- `sanitizeField` надёжно закрывает инъекции в line-based store.
- `atomic16.c` — корректный spinlock (acquire/release/yield-backoff, хеш-пул
  локов, CAS корректно обновляет `*expected`).
- `prof_preload.c` — правильная архитектура сигнальной диагностики: в хендлере
  минимум, символизация в отдельном потоке, прогрев unwinder в конструкторе.
- `wpe_render.c` — образцовая работа с libpng (setjmp/longjmp, освобождение на
  всех путях).
- Гигиена секретов: `.env` gitignored, пароль не попадает в ps/ssh-командную
  строку, key auth; SDK пинned по SHA256 и через bind-mount; overlay-mount для
  `/usr/libexec` полностью обратимый.
- Паттерн «pure headers без Qt/WebKit» под хост-тесты — правильная архитектура;
  константы в тестах совпадают с продом.

## Приоритетный план до релиза

1. **Убрать из README/CLAUDE.md фантомные фичи** (или реализовать) — иначе
   релиз вводит в заблуждение.
2. Починить две root-инъекции (`main.cpp:257`, `run-wpeqt-on-device.sh:15`)
   и `atomicWrite` (проверка записи + fsync + rename только при успехе).
3. Проверить на устройстве восстановление WebProcess (QTimer → glib-таймер).
4. Сделать crash handler async-signal-safe + добавить SIGBUS/SIGILL — это
   единственная диагностика на устройстве.
5. Разрулить мёртвый код: refreshpolicy/hintlabels/exit-armed/TLS-сигналы —
   подключить или удалить, поправить врущие комментарии.
6. rpath в бандл, SHA256 для тарболлов, warning/hardening-флаги,
   `set -euo pipefail` где нужно.
7. Аудит символов `__atomic_*` бандла; проверка размера буфера в
   `wpe_render.c:131`.
8. Усмирить логирование (категория + выключено по умолчанию), debounce записи
   профиля.

**Вердикт:** зрелая архитектура и аккуратное ядро, но статус «v0.8.0
release-ready, all features verified» не соответствует реальности — это
«solid beta с долгом по безопасности и документации». До публичного релиза
пункты 1–4 обязательны.
